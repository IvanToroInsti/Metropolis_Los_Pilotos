║                    AYUDA - MENU DE CONTROL                            ║
╚══════════════════════════════════════════════════════════════════════╝

DESCRIPCION:
    Script de control para gestionar contenedores Docker del proyecto
    'Los Pilotos'. Permite monitorear el servidor, gestionar contenedores,
    exportar logs, administrar la base de datos y realizar tareas de mantenimiento.

REQUISITOS:
    • Docker y Docker Compose instalados
    • Permisos de root para el menu de acciones (opcion 4)
    • Archivo docker-compose.yml en la misma ruta que el script

OPCIONES DEL MENU PRINCIPAL:

    1. Ver estado del servidor
       Ejecuta 'top' para mostrar procesos en tiempo real.
       Permite monitorear CPU, memoria y carga del sistema.

    2. Ver estado de los contenedores
       Lista TODOS los contenedores (activos o detenidos) mostrando:
       - Nombre
       - ID
       - Estado
       - Puertos
       - Tiempo desde su inicio

    3. Exportar logs de algun contenedor
       Permite guardar los logs de un contenedor en un archivo.
       - Seleccionas el contenedor manualmente
       - Puedes indicar ruta personalizada
       - Ruta por defecto: ./backups/[contenedor].log
       - Se crean directorios automáticamente si no existen

    4. Acciones
       [REQUIERE ROOT]
       Acceso al menú avanzado de administración (ver más abajo)

    5. Version
       Muestra la versión actual del script (0.1.0)

    6. Ayuda
       Muestra este archivo de ayuda (ayuda.txt)

    7. Salir
       Finaliza la ejecución del script


MENU DE ACCIONES (Opcion 4 - Requiere root):

    1. Acceder a la base de datos
       Conexión directa a MariaDB usando credenciales configuradas
       (host: 172.18.0.1, puerto: 3306)

    2. Acceder a contenedor
       Abre una terminal interactiva dentro de un contenedor:
       - Intenta usar bash
       - Si no existe, usa sh

    3. Crear copia de seguridad base de datos
       Genera un dump SQL en:
       ./dumps/dump-[fecha].sql
       - Se crea la carpeta automáticamente si no existe

    4. Reiniciar contenedor
       Reinicia un contenedor seleccionado manualmente

    5. Detener contenedor
       Detiene un contenedor específico

    6. Iniciar contenedores (todos)
       Levanta todos los servicios definidos en docker-compose.yml
       - Pregunta confirmación
       - Permite modo segundo plano (-d)

    7. Detener contenedores (todos)
       Ejecuta:
       docker compose stop

    8. Recrear contenedores - Volver a compilar
       Ejecuta:
       docker compose down
       docker compose up --build -d
       Útil tras cambios en Dockerfiles o configuración

    9. Eliminar contenedores y volúmenes
       Ejecuta:
       docker compose down -v
       ⚠ Elimina datos persistentes

    10. Limpieza de imágenes sin uso
        Ejecuta:
        docker system prune
        Elimina:
        - Imágenes no usadas
        - Contenedores detenidos
        - Redes y cache

    11. Insertar datos de prueba en base de datos
        Ejecuta un script SQL desde:
        ./pruebas/datos.sql

    12. Volver
        Regresa al menú principal


CONTENEDORES DEL PROYECTO (referencia):

    nginx     - Servidor web / proxy inverso
    web       - Frontend
    server    - Backend / API
    database  - Base de datos MariaDB


COMANDOS UTILIZADOS INTERNAMENTE:

    • docker ps / docker ps -a
    • docker logs
    • docker exec -it
    • docker restart / stop
    • docker compose up/down/stop
    • docker system prune
    • mysqldump
    • mariadb (cliente CLI)


NOTAS IMPORTANTES:

    • El menú de acciones solo funciona como root (EUID = 0)
    • Las rutas de backup y dumps se crean automáticamente
    • Los logs se guardan con extensión .log
    • Algunas acciones piden confirmación (Y/n)
    • El script usa rutas relativas al directorio donde se ejecuta
